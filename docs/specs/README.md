# אפיונים: הפורמט

התיקייה הזו מחזיקה את האפיונים של הריפו: מה בונים, לפי נושא.
האפיון הוא מקור האמת ל"מה". ה-issue מחזיק את ה"איך" ואת המצב.
למה כך: [221-spec-first.md](../decisions/221-spec-first.md).

הקובץ הזה מסביר את הפורמט, והבדיקה מדלגת עליו: הוא לא אפיון.
שלד של אפיון חדש: `skills/dev-setup/templates/spec.md`.

## קובץ לכל נושא
- **קובץ אחד לכל נושא:** `docs/specs/<topic>.md`, בשם קצר באנגלית.
- **חלק** הוא כותרת ברמה `##` עד `####` שמתחילה במזהה:
  ```markdown
  ### S-3.2 · שם החלק
  ```
- **כותרת בלי מזהה היא קיבוץ חופשי**, לא חלק. למשל `## שלב ראשון`, שמעל כמה חלקים.
- **שם הקובץ והמזהה ביחד מזהים חלק.** אותו מזהה יכול לחזור בשני קבצים שונים.

## המזהים
- **הצורה:** `S-<n>.<m>`, שני מספרים. `<n>` הוא הקבוצה בתוך הנושא, ו-`<m>` החלק בתוכה.
- **המזהה לא משתנה כשהשם משתנה.** issues ו-PRים מצביעים עליו, ושם חדש לא שובר אותם.
- **מספר שנמחק לא חוזר.** חלק שהוצא מסומן "מחוץ להיקף", ולא נמחק. חלק חדש מקבל את המספר הבא שלא היה בשימוש.
  את זה הבדיקה לא רואה, כי אין לה היסטוריה: זה נוהל.

## שורת המצב
השורה הלא ריקה הראשונה מתחת לכותרת של חלק:
1. `**מצב:** Done (#<N>)`: החלק נבנה, ב-issue מספר `<N>`. ה-PR של הקוד מוסיף את השורה.
2. `**מצב:** מחוץ להיקף`: הוחלט לא לבנות אותו.
3. בלי שורת מצב: החלק פתוח. "בעבודה" ו"לא התחיל" לא נכתבים בקובץ: הם נקראים מהתווית של ה-issue.

## שורת האפיון ב-issue
כל issue מצביע על החלקים שלו בשורה אחת, בסעיף "הקשר / קישורים", ליד `תלוי ב:`:
```
אפיון: docs/specs/<topic>.md S-3.2
```
1. **כמה מזהים מאותו קובץ** מותרים, מופרדים בפסיק. למשל באג שנוגע בשני חלקים.
2. **באנגלית:** `Spec:` במקום `אפיון:`.
3. **issue בבקלוג** (`status:backlog`) פטור: הוא הצעה, ומקבל אפיון כשהוא מאושר.
4. **באג:** לטופס של באג אין "הקשר / קישורים". הוא מצביע על החלק שהוא שובר בשורת `- **אפיון:**` בתוכנית המקוצרת שלו, והבדיקה קוראת גם אותה (#227).

## הבדיקה: `spec_check.py`
`skills/dev-setup/scripts/spec_check.py` רץ ב-CI בכל PR, דרך ה-action `skills/dev-setup/actions/spec-check`.
1. **שגיאה בקובץ מכשילה את ה-CI:** מזהה כפול באותו קובץ, כותרת `S-` שבורה (כמו `S-3` או `S-3.x`), חלק ברמה אחרת מ-`##` עד `####`, ושורת מצב לא מוכרת.
   ההודעה אומרת איזה קובץ, איזו שורה ומה לתקן.
2. **פער בין issue לאפיון רק מזהיר:** שורה שמצביעה על קובץ או מזהה שלא קיימים, issue פתוח בלי שורת אפיון, וחלק פתוח שאף issue פתוח לא מצביע עליו.
   הפער מופיע כאזהרה ב-PR ובטבלת הסטטוס, ולא משנה את קוד היציאה (#226).
3. **ריפו בלי אף אפיון** עובר את הבדיקה, ומזהיר על ה-issues הפתוחים בלי שורת אפיון.

הרצה מקומית, מהשורש של הריפו:
```
python skills/dev-setup/scripts/spec_check.py --table
python skills/dev-setup/scripts/spec_check.py --no-issues
```
1. `--table`: טבלה לכל קובץ: מזהה, שם, מצב, issue. המצבים: Done, מחוץ להיקף, בעבודה, לא התחיל (ה-issue ב-`status:explore` או `status:backlog`), ואין issue.
2. `--no-issues`: רק בדיקות הקובץ, בלי `gh` ובלי רשת.
