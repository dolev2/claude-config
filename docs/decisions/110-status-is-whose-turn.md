# הסטטוס לבדו אומר של מי התור, והלוח רק משקף את התוויות

**מצב:** בתוקף · **תאריך:** 2026-11-05 · **issue:** #110 (וגם #106, #111)

## רקע
כל משימה נשאה שתי תוויות שאמרו כמעט אותו דבר: סטטוס, ושל מי התור (`owner:*`). כל מעבר עדכן את שתיהן (#110).
הסנכרון עם הלוח היה דו-כיווני. כדי לדעת מי השתנה הוא כתב סמן מוסתר בגוף של כל issue והכריע לפי כלל.
גרירה בלוח יכולה הייתה להחזיר תוויות לאחור, ושתי תקלות הפילו אותו: issue שכבר על הלוח (#101), ושגיאה זמנית של GitHub (#105) (#111).

## החלטה
1. **הסטטוס לבדו אומר של מי התור.** אין תוויות `owner:*`, וכל מעבר הוא שינוי סטטוס אחד. `status:*` היא קבוצה בלעדית.
2. **תשובה של דולב, או תוכנית שהוא מחזיר, מחזירות את ה-issue ל-`status:explore`.** `dev-plan` רואה שכבר יש תוכנית ומעדכן אותה.
3. **התוויות הן מקור האמת, והלוח רק משקף אותן, בכיוון אחד.** גרירה בלוח נדרסת בסנכרון הבא. הסנכרון לא נוגע בגוף ה-issue.
4. **החריג היחיד:** issue שנפתח ישר מהלוח, בלי אף תווית סטטוס, מקבל את הסטטוס מהעמודה שלו פעם אחת. בלעדיו הוא נעלם מכל הסריקות.

## חלופות שנדחו
1. **תווית בעלים לצד הסטטוס:** כפילות. שתי תוויות לכל מעבר, ושמות הסטטוסים כבר אומרים של מי התור.
2. **סנכרון דו-כיווני עם סמן בגוף:** מחזיר תוויות לאחור אחרי גרירה, עורך את גוף ה-issue, ונפל בשתי תקלות.
3. **הלוח כמקור האמת:** דולב בחר בתוויות, והלוח לתצוגה בלבד (5.11.2026).
