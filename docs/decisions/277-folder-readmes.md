# מפת הריפו: README בשורש עם מבנה התיקיות, ו-README לכל תיקייה של קבוצה

**מצב:** בתוקף · **תאריך:** 2026-11-12 · **issue:** #277

## רקע
היו חמש מפות לריפו, וכל אחת חילקה אותו אחרת.

מדריך הקבצים היה טבלה אחת ארוכה ב-README שבשורש, ובתאים שלה הצטברו היסטוריה ומספרי issues (#255).

קשה היה למצוא בה תיקייה, וכל PR הוסיף לאותו קובץ.

## החלטה
1. **ה-README שבשורש מראה את מבנה התיקיות:** משפט לכל תיקייה, והפרק שלה באפיון.
2. **לכל תיקייה של קבוצת קבצים יש README משלה**, משפט לכל קובץ, שמסביר גם את תתי-התיקיות שלה.
3. **כל קובץ מתואר רק במדריך הקרוב אליו:** ה-README העמוק ביותר מעליו, ואם אין, זה שבשורש. `file_guide_check.py` אוכף את זה.
4. **חריגים:** תיקייה שכל קובץ בה נטען ככלל לכל סשן, ונתוני בדיקה.
5. **בלי היסטוריה ובלי מספרי issues בתאים**, ומה שכתוב במסמך בעלים מקבל הפניה ולא העתקה.

## חלופות שנדחו
1. **עמוד Artifact של מפת הריפו:** עוד מפה, שמתיישנת בלי בדיקה.
2. **קובץ צד "איפה זה גר":** כפילות של המדריך.
3. **מזהה חלק בכל בדיקה ובכל commit:** הרבה עבודה ידנית, בלי בדיקה שתופסת טעות.
4. **README לכל תיקייה, כולל קטנות ותיקיות באותו מבנה:** הרבה קבצים שחוזרים על עצמם (דולב, 11.11.2026).

## מחיר
קובץ חדש מעדכן את ה-README של התיקייה שלו ולא את זה שבשורש, והבדיקה מסובכת יותר.

ריפו שהותקן קודם ממשיך לעבור עם README אחד, ומקבל את המבנה רק כשנוגעים בו.
