# evals

תרחישי הסקילים: כל תרחיש מריץ סקיל אחד מול GitHub מדומה, ובודק מה הוא עשה.
כך שינוי בטקסט של סקיל שמקלקל כלל נתפס לפני המיזוג.
מתי הם רצים ואיך: `skills/dev-setup/reference/tests.md`. למה כך: `docs/decisions/183-skill-evals.md`.

## מדריך קבצים

משפט לכל קובץ ולכל תת-תיקייה.
הבדיקות, `test_*.py`, בודקות את העטיפה ואת ה-gh המדומה בלי מודל.
התוצאות נכתבות ל-`results/`, שלא נכנס ל-git.

### ההרצה
| קובץ | מה הוא |
|---|---|
| `run.py` | בוחר את התרחישים לפי ה-diff, בונה plugin זמני מ-`skills/`, ומריץ אותם במודל של הסשן. |
| `summary.py` | מדפיס שורה לכל סקיל, וסיבה לכל תרחיש שנכשל. |
| `scaffold.sh` | מכין לכל תרחיש ריפו דוגמה מ-`fixture/`, עם remote מקומי. |
| `conftest.py` | מוציא את `results/` ואת `fixture/` מהבדיקות, כי יש בהם עותקים ובדיקות שלא של התיקייה. |

### ה-gh המדומה
| קובץ | מה הוא |
|---|---|
| `bin/gh` | הפקודה `gh` שהתרחיש רואה, ומפנה ל-`fake_gh.py`. |
| `fake_gh.py` | ה-gh המדומה: עונה על הפקודות של הצינור מקובץ מצב, ורושם כל קריאה בשביל הבודקים. |
| `fake_gh_state.py` | המצב של GitHub המדומה: issues, תוויות ו-PRים, בקובץ JSON אחד לכל תרחיש. |
| `fake_gh_rest.py` | התשובות של `gh api` ב-REST. |
| `fake_gh_graphql.py` | התשובה לשאילתת ה-GraphQL היחידה שהצינור מריץ: תתי-ה-issues והחוסמים של issue. |

### התיקיות
| תיקייה | מה היא |
|---|---|
| `cases/` | התרחישים, תיקייה לכל תרחיש: ההנחיה, המצב ההתחלתי והבודקים. |
| `holdout/` | הסט השמור בצד, באותו מבנה, שלא משנים יחד עם סקיל. |
| `fixture/` | הריפו המדומה שהסקילים רצים עליו, וה-README שבתוכו הוא חלק מהדוגמה ולא מדריך. |
