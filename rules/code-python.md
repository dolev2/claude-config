# נהלי קוד: Python

בנוסף לנהלים הכלליים (`code-general.md`).
איפה גרה כל שכבה בריפו מסוים כתוב ב-`CLAUDE.md` שלו.

## שלוש שכבות
- **route דק:** מקבל קלט, בודק הרשאות, קורא ללוגיקה ומחזיר תשובה. בלי חישובים ובלי שאילתות.
- **לוגיקה עסקית בלי HTTP:** לא מייבאת FastAPI, לא מכירה `Request` ולא זורקת `HTTPException`.
  כך אפשר לבדוק אותה בלי שרת, ולקרוא לה גם מפקודה או מסקריפט.
  כשלון עסקי הוא חריגה משלה, וה-route מתרגם אותו לקוד HTTP.
- **גישה למסד במקום אחד:** שאילתות לא מפוזרות בין ה-routes והלוגיקה.
- **מקור חיצוני מאחורי שכבה משלו:** לוגיקה עסקית לא קוראת ישירות ל-API של ספק.

## סגנון
- `snake_case` לפונקציות ולמשתנים, `PascalCase` למחלקות, `UPPER_CASE` לקבועים.
- type hints בכל חתימה של פונקציה.
- import בראש הקובץ. import בתוך פונקציה רק כדי לשבור מעגל, עם הערה שאומרת את זה.
- בלי `except:` ריק ובלי `except Exception` שבולע את השגיאה בשקט. תופסים רק מה שיודעים לטפל בו.

## בדיקות
מה בודקים בכל שינוי: `code-tests.md`. כאן רק הפרטים של pytest.
- קובץ `test_<module>.py` ליד הבדיקות הקיימות של אותו אזור.
- נתונים דרך fixtures (`conftest.py` של האזור), וקבצים ב-`tmp_path`. לא נתיב קבוע ולא תיקיית הריפו.
- endpoint נבדק דרך ה-test client של ה-framework, מול מסד בדיקתי שה-fixture יוצר ומוחק.
- mock של שירות חיצוני בגבול השכבה שלו (`monkeypatch` על מודול הספק), לא בתוך הלוגיקה העסקית.
- כמה מקרים של אותה התנהגות: `pytest.mark.parametrize`, לא העתקה של הבדיקה.
