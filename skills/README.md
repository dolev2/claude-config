# skills

הסקילים של צינור העבודה, תיקייה לכל סקיל.
כל תיקיית סקיל היא אותו מבנה, קובץ `SKILL.md` אחד, ולכן אין לה README משלה.
המנגנון שהסקילים מפעילים יחד: `dev-setup/reference/pipeline.md`.

## מדריך קבצים

| סקיל | מה הוא עושה |
|---|---|
| `dev-spec/` | כותב אפיון לנושא כ-PR, והמיזוג שלו הוא האישור של ה"מה". |
| `dev-issue/` | פותח issues בפורמט של הצינור, ומפרק אפיון שמוזג ל-issue לכל חלק. |
| `dev-next/` | בוחר את המשימה הבאה בספרינט, ושולח אותה לתכנון או לקוד. |
| `dev-plan/` | שלב התכנון: חוקר וכותב את התוכנית בגוף ה-issue. |
| `dev-code/` | שלב הקוד: מממש את התוכנית ומוסר PR לסקירה, בלי למזג. |
| `dev-ship/` | הדרך היחידה למזג: rebase, בדיקות, CI, מיזוג וניקוי, על בקשה של דולב. |
| `dev-orchestrate/` | מריץ את כל הספרינט מסשן ענן אחד, עם סשן-בן לכל משימה. |
| `status/` | סקירת העבודה בארבע טבלאות ובגרף חסימות, בלי לשנות כלום. |
| `dev-setup/` | מתקין את הצינור בריפו, ומחזיק את החלקים המשותפים לכל הסקילים ([README](dev-setup/README.md)). |
