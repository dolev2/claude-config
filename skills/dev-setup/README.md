# dev-setup

הסקיל שמתקין את הצינור בריפו (`SKILL.md`), וגם הבית המשותף של כל הסקילים `dev-*`.
מי מחזיק כל כלל של הצינור, ומי מפנה אליו: `reference/owners.md`.

## מדריך קבצים

משפט לכל קובץ.
הבדיקות, `scripts/test_*.py`, בודקות את הסקריפטים, את ה-actions ואת התבניות, ורצות ב-CI.

### `reference/`: מסמכי הצינור
הסקילים קוראים את קבצי ה-`.md` כאן, כל סקיל את מה שה-"Read first" שלו מונה.

| קובץ | מה הוא |
|---|---|
| `pipeline.md` | הליבה של המנגנון: אוצר המילים, הספרינטים והכללים שלא משתנים, שכל סקיל `dev-*` קורא. |
| `owners.md` | מפת הבעלים: לכל כלל בצינור, הקובץ שמחזיק את הנוסח המלא שלו. |
| `issue-body.md` | איך קוראים את כל ההקשר של issue, ופורמט התוכנית בגוף שלו. |
| `dependencies.md` | קישורי Blocked by, פיצול ואיחוד, והדירוג בספרינט. |
| `git-flow.md` | issue אחד בריצה, שער ה-WIP, עותק העבודה בכל שלב, ו-branch ו-PR. |
| `tests.md` | אילו בדיקות רצות ומתי: ממוקד בזמן הכתיבה, ומלא פעם אחת אחרי ה-rebase. |
| `review-app.md` | הרמת האפליקציה של ה-PR לסקירה, ועצירה שלה. |
| `ux.md` | הבדיקה של חוויית המשתמש: הסעיף בתוכנית, והמעבר בדפדפן לפני המסירה. |
| `specs.md` | שלב האפיון: מתי הוא רץ, הפירוק ל-issues, וסימון חלק כגמור. |
| `chat-decisions.md` | ההחלטות של דולב בחלון השאלות, ומה נחשב החלטה. |
| `lessons.md` | לקח שסוכן מציע בסוף ריצה, ואיך הוא נכנס לכלל באישור של דולב. |
| `after-merge.md` | מה קורה אחרי מיזוג: ההצעה לסשן הבא, והפרסום מחדש של עמוד Artifact. |
| `parallel.md` | עבודה במקביל: סוכן לכל חלק של התוכנית, והחיבור שלהם. |
| `setup.md` | מה ש-`dev-setup` מתקין ולמה, שרק הוא קורא. |
| `board.md` | לוח ה-Project בהתקנה: יצירה, קישור ותצוגות. |
| `repo-files.md` | הקבצים שההתקנה מוסיפה לריפו: lint, Netlify ומדריך הקבצים. |
| `orchestrate.md` | המתזמר והסשנים-הבנים, והחוזה שעובר לכל בן מילה במילה. |
| `orchestrate-spec.md` | בן אפיון במתזמר: הצעה ששויכה לספרינט מקבלת אפיון לפני כל בן אחר. |
| `cloud.md` | עבודה מסשן ענן ומהטלפון, וטבלת הפקודות של GitHub בענן. |
| `diagram.md` | תרשים ה-Mermaid של הצינור לבני אדם, שאף סקיל לא קורא. |
| `issue-lifecycle.html` | העמוד "חייו של issue" לבני אדם, שמפורסם כ-Artifact. |
| `issue-lifecycle-en.html` | אותו עמוד באנגלית, שמפורסם כ-Artifact נפרד. |

### `scripts/`: הסקריפטים של הסקילים
| קובץ | מה הוא |
|---|---|
| `pipeline_info.py` | קורא מהריפו כל מה שמשתנה בין ריפואים, וכל סקיל מתחיל בו. |
| `sprint_rule.py` | הכלל היחיד לספרינט הנוכחי: ה-milestone הפתוח הנמוך ביותר שיש בו issue פתוח. |
| `rank_issues.py` | מדרג את ה-issues בספרינט, בסדר של `dev-next`, `dev-plan` ו-`dev-code`. |
| `audit_sprint.py` | בודק את קישורי ה-Blocked by של כל הספרינט: קישור חסר, מעגל וחפיפת קבצים. |
| `pause_reason.py` | אומר אם issue מושהה, ומה הסיבה. |
| `sprint_state.py` | מחזיר את מצב הספרינט כ-JSON אחד, בשביל המתזמר. |
| `sprint_github.py` | הקריאות ל-GitHub של `sprint_state.py`, כדי שהבדיקות שלו ירוצו בלי רשת. |
| `sprint_proposals.py` | ההצעות המאושרות בספרינט, והשלב של האפיון של כל אחת. |
| `pipeline_shas.py` | מזהי הצינור ב-`main`, כדי שהמתזמר יזהה שהצינור השתנה באמצע ספרינט. |
| `watch_children.py` | מחכה ברקע שה-issue של בן ישתנה, ומעיר את המתזמר. |
| `wait_ci.py` | מחכה שה-CI של commit אחד יסתיים, ומדפיס את התוצאה. |
| `work_status.py` | מדפיס את הטבלאות של `/status` ואת גרף החסימות. |
| `status_graph.py` | בונה את גרף החסימות של `/status` כבלוק Mermaid. |
| `status_page.py` | בונה את העמוד הלחיץ של גרף החסימות: קישור למשימה, ל-PR ולסשן בכל צומת (#355). |
| `gh_rest.py` | קורא issues מ-GitHub ב-REST בלבד, כי GraphQL חסום בענן. |
| `issue_body.py` | קורא את הסעיפים של גוף issue: המטרה, התלות, האפיון והתוכנית. |
| `spec_check.py` | בודק את קבצי האפיון: שגיאה בקובץ מכשילה, ופער מול ה-issues מזהיר. |
| `spec_parse.py` | קורא קובץ אפיון אחד: החלקים ושורת המצב של כל אחד. |
| `spec_toc.py` | בונה את תוכן העניינים של קובץ אפיון, ובודק שהוא לא התיישן. |
| `spec_changes.py` | משווה את האפיון בין שני refs, ואומר מה קורה ל-issue של כל חלק שהשתנה. |
| `board_views.py` | יוצר את שתי התצוגות של הלוח בהתקנה. |
| `port_check.py` | בודק אם פורט תפוס ובוחר פורט פנוי, ב-IPv4 וב-IPv6. |
| `lint_check.py` | מדווח על הגדרות lint, או עותק של בדיקת המדריך, שחסרים או שסטו מהתבנית. |
| `conftest.py` | מוסיף את `actions/project-sync/` לנתיב, כדי שהבדיקות ייבאו את המודולים בשמם. |

### `actions/`: ה-actions שכל ריפו קורא להם
| קובץ | מה הוא |
|---|---|
| `open-questions-gate/` | שער השאלות הפתוחות: `action.yml` מריץ את `check_open_questions.py`. |
| `spec-check/` | בדיקת האפיונים מ-`tests.yml`: `action.yml` מריץ את `scripts/spec_check.py`. |
| `project-sync/action.yml` | הסנכרון מהתוויות ללוח, בכיוון אחד, שכל ריפו עם לוח קורא לו. |
| `project-sync/sync_project.py` | נקודת הכניסה של הסנכרון: ההגדרות, הלולאה על ה-issues ומה מודפס. |
| `project-sync/sync_rules.py` | הכללים של הסנכרון, בלי קריאות ל-GitHub, כדי שאפשר לבדוק אותם לבד. |
| `project-sync/closing.py` | מה issue סגור מקבל: גמור, או כרטיס שעובר לארכיון. |
| `project-sync/board.py` | קריאה וכתיבה של הלוח מצד ה-issue. |
| `project-sync/sprint_rule.py` | עותק של `scripts/sprint_rule.py`, כי הסנכרון מורד כתיקייה שטוחה. |
| `project-sync/sprint_view.py` | מזיז את התצוגה "ספרינט נוכחי" לספרינט הנוכחי. |
| `project-sync/gh_api.py` | הקריאות ל-`gh`, עם ניסיון חוזר על שגיאה זמנית. |
| `project-sync/sweep_all.py` | הסקר המתוזמן של כל הלוחות, שרץ מהריפו הציבורי `dolev2/.github`. |
