מה קורה ב-git

ה-branch נולד ב-remote בזמן התכנון, נכתב ב-worktree נפרד, מתעדכן ב-rebase, ונכנס ל-main ב-squash.

התיקייה הראשית לא מחליפה branch אף פעם.

  • main: הקו הראשי של הריפו
  • branch: שרשרת commits. כל עיגול הוא commit
  • branch מקווקו: ריק, או commits שהוחלפו ב-rebase
  • מסגרת מקווקוות: worktree, כלומר תיקייה במחשב. הקו שבתוכה הוא ה-branch שפתוח בה
  • חץ שחור: commits עוברים, בין GitHub למחשב או בין branches
  • חץ אדום: push בכוח
  1. 1
    dev-plan יוצר את ה-branch ב-GitHubבלי checkout: ה-branch קיים רק ב-GitHub, והתיקייה במחשב נשארת על main.
    הוא ריק: מצביע על אותו commit כמו main.
    git push origin origin/main:refs/heads/claude/issue-42-slug
  2. 2
    dev-code מוריד אותו ל-worktreeתיקייה נפרדת במחשב, רק ל-issue הזה.
    קודם מורידים את ה-branch של ה-issue מ-GitHub:
    git fetch origin claude/issue-42-slug
    ואז יוצרים ממנו branch מקומי ותיקייה, בפקודה אחת:
    git worktree add ../worktrees/<repo>-issue-42 -B claude/issue-42-slug origin/claude/issue-42-slug
  3. 3
    סוכנים במקביל, רק כשהתוכנית מחלקתכל סוכן בתיקייה משלו (worktree זמני), עם branch זמני משלו. commit בלבד, לא push.
    כל ה-worktrees חולקים מאגר commits אחד, ולכן ה-commits של הסוכן זמינים לסשן הראשי בלי GitHub.
  4. 4
    קובץ מחוץ לחלק של הסוכןסוכן שרוצה לשנות קובץ מחוץ לחלק שלו, למשל README.md, נחסם, וכותב את השינוי כבקשה בדוח שלו (נאכף בעריכה: guard_parallel_parts.py, #82).
    הסשן הראשי מיישם את הבקשה בשלב 5, אחרי האיחוד.
    בלי חלוקה: אין סוכנים. הסשן הראשי כותב לבד, ישר ב-worktree, ומדלג לשלב 6.
  5. 5
    איחוד: הסשן הראשי אוסף את העבודהלכל סוכן: git diff --name-only, ובדיקה שהוא נגע רק בקידומות שלו מהתוכנית.
    אחר כך git cherry-pick מה-branch של הסוכן ל-branch המקומי של ה-issue. קודם סוכן א, אחר כך סוכן ב.
    התנגשות: git cherry-pick --abort, ועצירה.
    אחרי האיחוד: הסשן הראשי מיישם את הבקשות מהדוחות, ומוחק את ה-worktrees וה-branches הזמניים.
  6. 6
    עדכון מול main, לפני הבדיקותהפעם מורידים את main, לא את ה-branch של ה-issue:
    git fetch origin main
    git rebase origin/main
    ה-commits נבנים מחדש על main העדכני, עם מזהה חדש.
    התנגשות: git rebase --abort, תגובה ב-issue, ואין PR.
  7. 7
    בדיקה מלאה, push ראשון ו-PRlint ואז כל החבילות, פעם אחת, במקביל.
    push רגיל מספיק: ב-GitHub עוד אין commits לדרוס.
    gh pr create עם Closes #42, ואז CI, סוכן סקירה ואפליקציית סקירה, ובה בדיקת חוויית משתמש.
    Closes #42 רק מקשר את ה-PR ל-issue. ה-issue נסגר לבד רק כשה-PR ממוזג, בשלב 9.
  8. 8
    סבב תיקון, אם צריךבאותו worktree, ושוב rebase.
    ה-rebase בנה מחדש commits שכבר ב-GitHub, ולכן צריך כוח:
    git push --force-with-lease
    הוא מסרב אם מישהו אחר דחף בינתיים, למשל עריכה בממשק של GitHub.
  9. 9
    squash merge, רק כשדולב מבקש בצ'אטgh pr checks --watch --fail-fast
    gh pr merge --squash
    חלון אישור קופץ לפני כל merge.
    ה-branch ב-GitHub נמחק לבד, בהגדרה Automatically delete head branches של הריפו.
  10. 10
    ניקוי במחשבעוצרים את אפליקציית הסקירה, ואז git worktree remove.
    מוחקים את ה-branch המקומי, ו-git pull --ff-only ב-main.
