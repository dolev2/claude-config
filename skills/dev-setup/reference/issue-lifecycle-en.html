What happens in git

The branch is born on the remote during planning, written in a separate worktree, updated with rebase, and lands in main as a squash.

The main folder never switches branches.

  • main: the repo's main line
  • branch: a chain of commits. Each circle is a commit
  • dashed branch: empty, or commits replaced by a rebase
  • dashed frame: a worktree, meaning a folder on your computer. The line inside is the branch open in it
  • black arrow: commits move, between GitHub and your computer or between branches
  • red arrow: a forced push
  1. 1
    dev-plan creates the branch on GitHubNo checkout: the branch exists only on GitHub, and the folder on your computer stays on main.
    It is empty: it points at the same commit as main.
    git push origin origin/main:refs/heads/claude/issue-42-slug
  2. 2
    dev-code pulls it into a worktreeA separate folder on your computer, just for this issue.
    First, fetch the issue's branch from GitHub:
    git fetch origin claude/issue-42-slug
    Then create a local branch and a folder from it, in one command:
    git worktree add ../worktrees/<repo>-issue-42 -B claude/issue-42-slug origin/claude/issue-42-slug
    In a cloud session there is no worktree: the session's clone is its own, so git checkout -B runs directly in it.
  3. 3
    Parallel agents, only when the plan splits the workEach agent works in its own folder (a temporary worktree), with its own temporary branch. Commit only, no push.
    All worktrees share one commit store, so the agent's commits reach the main session without GitHub.
  4. 4
    A file outside the agent's partAn agent that wants to change a file outside its part, such as README.md, is blocked and writes the change as a request in its report (enforced on edit: guard_parallel_parts.py, #82).
    The main session applies the request in step 5, after combining.
    No split: no agents. The main session writes alone, directly in the worktree, and skips to step 6.
  5. 5
    Combine: the main session gathers the workFor each agent: git diff --name-only, and a check that it touched only its own prefixes from the plan.
    Then git cherry-pick from the agent's branch into the issue's local branch. Agent A first, then agent B.
    Conflict: git cherry-pick --abort, and stop.
    After combining: the main session applies the requests from the reports, then deletes the temporary worktrees and branches.
  6. 6
    Update against main, before the testsThis time fetch main, not the issue's branch:
    git fetch origin main
    git rebase origin/main
    The commits are rebuilt on top of the latest main, with new IDs.
    Conflict: git rebase --abort, a comment on the issue, and no PR.
  7. 7
    Full test run, first push and PRLint, then every package, once, in parallel.
    A plain push is enough: GitHub has no commits yet to overwrite.
    gh pr create with Closes #42, then CI, a review agent and the review app, where the user experience is checked.
    Closes #42 only links the PR to the issue. The issue closes on its own only when the PR is merged, in step 9.
  8. 8
    Fix round, if neededIn the same worktree, and rebase again.
    The rebase rebuilt commits that are already on GitHub, so a forced push is needed:
    git push --force-with-lease
    It refuses if someone else pushed in the meantime, for example an edit in the GitHub UI.
  9. 9
    Squash merge, only when Dolev asks in the chatgh pr checks --watch --fail-fast
    gh pr merge --squash
    In a cloud session: the GitHub MCP tool merge_pull_request.
    An approval prompt pops up before every merge, whichever way it runs.
    The branch on GitHub deletes itself, through the repo's Automatically delete head branches setting.
  10. 10
    Cleanup on your computerStop the review app, then git worktree remove.
    Run git fetch --prune, and git pull --ff-only in the main folder, only when it is on main and clean. Then delete the local branch.
    In a cloud session there is no worktree to remove: git checkout --detach origin/main, then delete the local branch.

The life of a cloud session

The environment is the recipe: network, variables, secrets and a setup script, saved in the account. The container is the temporary machine built from it.

The conversation is kept on the server. The container is deleted when the session is idle, and built again when you come back to it.

  1. Send

    Dolev picks an environment, a repo and a branch, and sends a message.

  2. New container

    A clean machine. The environment's network rules (proxy), variables and secrets take effect.

  3. Clone

    The session's repo is cloned into the container.

  4. Setup script

    Copies claude-config's main into ~/.claude.

    A failing script stops the session, so this one never fails (#132).

  5. Claude Code starts

    cloud_refresh.py pulls main, and CLAUDE.md, the rules and the skills load.

  6. Work

    Plan or execute, commit and push. Only what is pushed is kept.

  7. Idle time

    The container is deleted, with every file in it.

  8. Return or archive

    Return to the session: a new container, from step 2. The conversation continues.

    Archive: the conversation stays read-only.

Kept: the conversation, the environment settings, and what was pushed to GitHub.

Gone: files that were not pushed, and tools installed by hand in the session.

The orchestrator: a whole sprint from one session

Cloud only, and only when Dolev writes "run the sprint". The skill: dev-orchestrate. The contract: reference/orchestrate.md.

The children go through the same pipeline as above. The orchestrator remembers nothing between checks: every check rebuilds the picture from GitHub and the sessions' tags.

  1. Start

    Dolev asks. The orchestrator shows what opens now, what waits on a blocker, and what waits for him.

  2. Check

    sprint_state.py says what is ready for a child, what waits on a shared file, and what is ready to merge.

    A skill, script or hook changed on main: refresh ~/.claude and read them again.

    The global instructions, rules or settings changed, or the refresh failed: recommend a new orchestrator session to Dolev, and this orchestrator stops.

  3. A child per free task

    Up to 3 at a time, tagged issue:N. One child plans, a separate one codes.

  4. The child's contract

    It never asks Dolev, never touches links, never merges, and calls no session tools: no messages, no renaming its session (the service raises a prompt on each call). Its report is what it leaves on GitHub: the plan, the label, a comment and the PR.

  5. After a change

    A background watch (watch_children.py) wakes the orchestrator when a child's label moves or a comment lands. The orchestrator checks GitHub: the plan, the PR and its CI, and no stray branch or label.

  6. One question window

    Plan answers, approvals, and one merge at a time. Only Dolev decides.

  7. A bug or the quota

    A bug that hurts others: an issue, Blocked by, the hurt children stopped, and a child that fixes it.

    Quota in overage: no new child, and Dolev is asked.

  8. End of the sprint

    Nothing to open, ask or merge: a summary, and the loop stops.

    The summary lists the branches of closed tasks still on GitHub, for Dolev to delete by hand: the cloud cannot delete a branch.

Git rules that always apply

From rules/git.md. They apply in every repo, even when no skill is running.

Branch from origin

A branch is cut from origin/main after git fetch.

The local main can be several merges behind.

Convention

Rebase before testing

Rebase first, then run the tests.

This catches a hidden conflict: two valid changes that break together.

Convention

Rebase, not merge

History stays linear.

Every PR closes as a squash.

Convention

Only force-with-lease

--force silently overwrites other people's commits.

Enforced: block_force_push.py

Merge only with approval

An approval prompt pops up before every merge: gh pr merge, gh api or the MCP tool.

If Dolev declines: stop, and don't work around it.

Enforced: ask rule and hook

After a merge: offer /compact

The turn's last message ends with "What's open" and a full /compact block.

Forgotten: one more message with the block. Whether to compact stays Dolev's call.

Enforced: compact_after_merge.py

A conflict means stop

git rebase --abort, and report the files.

Never resolve by taking one side wholesale.

Convention

Never switch branches in the main folder

Another session or Dolev may be working there.

Work in a worktree.

Enforced in ~/.claude: guard_main_folder.py
