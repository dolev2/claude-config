# בדיקות

- **הפקודות הן של ה-repo**, מ-CLAUDE.md. פקודות ה-lint הן חלק מהן, וה-CI מריץ אותן לפני הבדיקות. בלי פקודות שם: מה שה-CI מריץ. בלי שניהם: לשאול את
  דולב.
- **חבילות מותנות.** אם CLAUDE.md מגדיר חבילה שרצה רק כשנוגעים באזור מסוים (למשל `-m live`
  ב-WayOut כשנוגעים ב-`backend/data_sources/`), בודקים את ה-diff מול `origin/<default>`
  (`git diff --name-only origin/<default>...HEAD`) ומריצים אותה כשהשינוי נוגע באזור.
- **תרחישי הסקילים (claude-config בלבד):** `python evals/run.py --model <המודל של הסשן>`, כשה-diff נוגע בסקיל מכוסה, ב-`skills/dev-setup/reference/` או ב-`evals/`.
  היא בוחרת את התרחישים לפי ה-diff בעצמה, רצה פעם אחת אחרי ההרצה המלאה, ומדווחת שורה לכל סקיל עם העלות (`dev-code` שלב 7).
  בענן וב-Linux בלבד: Bash בתרחיש רץ רק ב-sandbox, שצריך `bubblewrap` ו-`socat`. ב-Windows לא רצה, ואומרים את זה במסירה.
  חסרים: מתקינים, עם `apt-get update` קודם (בלעדיו apt לא מוצא אותן), ומריצים שוב:
  `(apt-get update -qq && apt-get install -y -qq bubblewrap socat) >/dev/null 2>&1`.
  ההצעה להוסיף את השורה לסקריפט ההתקנה של סביבת הענן (`cloud.md`) מחכה לאישור של דולב.
  למה כך: `~/.claude/docs/decisions/183-skill-evals.md`.
  **בודק תבנית (`type: regex`) נכתב בלי דגל בתוך התבנית**, כמו `(?m)` או `(?s)`: המנוע של התרחישים לא תומך בו, והבודק נכשל גם כשהסקיל צדק.
  שורה שלמה בפלט נבדקת כ-`(?:^|\n)<השורה>\n`, ולא כ-`(?m)^<השורה>$` (לקח מ-#310, PR #313, 12.11.2026).
- **repo בלי חבילה אוטומטית**, ש-CLAUDE.md שלו מגדיר בדיקה ידנית (למשל preview בדפדפן לאתר

### מתי רץ מה: ממוקד בפיתוח, מלא פעם אחת אחרי ה-rebase

החבילה המלאה אחרי כל תיקון קטן מכפילה את זמן הריצה פי כמה (claude-config #74).

**האזור של כל חבילה נגזר מהנתיב שבפקודה שלה** ב-CLAUDE.md: `pytest backend/tests` שייכת ל-`backend/`, `npm --prefix frontend test` ל-`frontend/`.
חבילה שאין נתיב בפקודה שלה (`pytest` או `npm test` מהשורש) שייכת לכל האזורים.
חבילה מותנית (הסעיף הקודם) שומרת על האזור שהגדיר לה CLAUDE.md.
הכלל מניח שאזורים לא חולקים קוד. קוד משותף לכמה אזורים נחשב מחוץ לכל אזור.
קובץ מחוץ לכל אזור (קוד משותף, הגדרות בשורש, lockfile, workflow, `.env.example`) שייך לכל האזורים.
הקבצים ששונו: `git diff --name-only origin/<default>...HEAD`, ועוד מה שעוד לא נכנס ל-commit (`git status --porcelain`).

- **בזמן הפיתוח (לפני ה-rebase):** לא מריצים חבילה מלאה, אלא רק את הבדיקות של האזור שהשתנה.
  בתוך האזור, קודם קבצי הבדיקה של המודול או הקומפוננטה שנגעו בהם (`test_<module>.py`, `<Component>.test.jsx`).
  אין קובץ כזה: תיקיית הבדיקות של האזור.
  בדיקה שנכשלה רצה שוב לבדה (`pytest <file>::<test>`, `vitest run <file>`).
- **אחרי ה-rebase:** קודם ה-lint, ואז כל החבילות, פעם אחת.
  חבילות של אזורים שונים רצות בו-זמנית, בפקודת Bash אחת.
  לכל חבילה קובץ לוג משלה וקוד יציאה משלה, והפקודה כולה נכשלת אם אחת מהן נכשלה.
  הסוגריים סביב כל חבילה שולחים ללוג גם פקודה מורכבת (`cd frontend && npm test`).
  הצורה עובדת ב-Git Bash, ב-Linux וב-macOS:
  ```bash
  L=$(mktemp -d)
  ( <backend suite> )  > "$L/backend.log"  2>&1 & B=$!
  ( <frontend suite> ) > "$L/frontend.log" 2>&1 & F=$!
  wait $B; RB=$?; wait $F; RF=$?
  tail -n 5 "$L"/*.log
  echo "backend exit $RB, frontend exit $RF"
  [ $RB -eq 0 ] && [ $RF -eq 0 ]
  ```
  קוד יציאה שאינו 0: קוראים את הלוג של אותה חבילה.
  repo עם חבילה אחת מריץ אותה כרגיל.
- **תיקון אחרי ההרצה המלאה** (בדיקה שנכשלה, ממצא של סוקר הקוד, CI אדום): ה-lint, ושוב בשלמותה רק החבילה של האזור שהתיקון נגע בו.
  תיקון בקובץ מחוץ לכל אזור: הכל.
