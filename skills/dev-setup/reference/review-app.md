# הרמה לסקירה

## הרמה לסקירה: האפליקציה של ה-PR, וקישור אליה

כש-`dev-code` מוסר PR לסקירה, האפליקציה כבר רצה מה-worktree של ה-PR, ובמסירה יש קישור שדולב
פותח בכרום.

האפליקציה עולה מיד אחרי פתיחת ה-PR, יחד עם CI ועם סוכן הסקירה, ולא אחרי ש-CI ירוק
(claude-config #73). אם בסוף אין מסירה, עוצרים אותה (למטה, "עצירה").

### הסעיף ב-`CLAUDE.md` של ה-repo

```markdown
## הרמה לסקירה
- פקודה: `<command>` (רצה מהשורש של ה-worktree)
- פורטים: `5173` (frontend, `PORT`), `8000` (backend, `BACKEND_PORT`)
- כתובת: `http://localhost:5173`
```

או שורה אחת: `אין אפליקציה.` (כמו ב-claude-config).

- **הפקודה בנתיבים יחסיים**, ולא `launch.json` עם נתיבים מוחלטים: זה מריץ את התיקייה הראשית ולא
  את ה-PR. היא אחראית גם להתקנות שה-worktree החדש צריך (`node_modules`, venv).
- **הפקודה רצה רק על המחשב של דולב**, ולכן מותר לה להיות Windows בלבד (`.cmd`, `.ps1`). היא
  מסומנת ככזו במדריך הקבצים (`rules/env-windows.md`).
- **לכל פורט, משתנה הסביבה שמעביר לו פורט אחר**, כולל רכיב שפונה לרכיב אחר (proxy). פורט בלי
  משתנה כתוב `קבוע`. רק כשלכל הפורטים יש משתנה, אפשר להרים עותק על פורטים פנויים.
- **הכתובת** משתמשת בפורט הראשון ברשימה.

### מתי מדלגים

בלי מסירת קישור, עם שורה במסירה שאומרת למה:
- אין סעיף ב-`CLAUDE.md`, או `אין אפליקציה`.
- הסשן לא רץ על המחשב של דולב (ענן, CI): קישור localhost לא ייפתח אצלו.

### קובץ הרישום

מה שהורם לסקירה רשום ב-`$(git rev-parse --git-common-dir)/review-app.json`, אחד לכל repo, משותף
לכל ה-worktrees:

```json
{"branch": "claude/issue-42-...", "worktree": "<path>", "ports": [5173, 8000], "pids": [1234, 5678], "url": "http://localhost:5173"}
```

### הסדר

1. **בודקים כל פורט** (עובד בכל מערכת; יציאה 0 פירושה תפוס):
   ```bash
   python "$HOME/.claude/skills/dev-setup/scripts/port_check.py" busy <port>
   ```
   פורט תפוס כשמשהו עונה ב-`127.0.0.1` **או** ב-`::1`. Vite על Node 17 ומעלה מאזין ל-`localhost`
   רק ב-`::1`, ובדיקה של `127.0.0.1` לבד ראתה אותו כפנוי (CRM #84, claude-config #52).
2. **הכל פנוי:** מריצים את הפקודה ברקע מתוך ה-worktree, מחכים עד דקה שכל הפורטים יענו, ורושמים
   את קובץ הרישום עם ה-PID של מי שמאזין לכל פורט. לא עלתה: שורת השגיאה האחרונה נכנסת למסירה.
3. **תפוס, ובקובץ הרישום ה-branch הזה:** לא מרימים שוב. מצרפים את הקישור מהקובץ.
4. **תפוס, ובקובץ הרישום branch אחר:** זו אפליקציה של PR קודם שהורם לסקירה. עוצרים אותה (למטה),
   מוחקים את הקובץ, וממשיכים כמו בשלב 2. המסירה האחרונה מנצחת; את ה-PR הקודם אפשר להרים שוב
   לפי בקשה.
5. **תפוס, ואין רישום** (למשל דולב מריץ את `master`): **לא נוגעים בה.**
   - לכל הפורטים יש משתנה: בוחרים פורטים פנויים בשתי הכתובות
     (`python "$HOME/.claude/skills/dev-setup/scripts/port_check.py" free`, פעם לכל פורט),
     מריצים עם המשתנים, ורושמים.
   - אחרת: מצרפים את הקישור עם אזהרה שהוא מציג קוד אחר, ומי תופס את הפורט (למטה). מציעים להרים
     את ה-PR כשהפורט יתפנה.

### מי תופס את הפורט

שם התהליך, ה-PID ושורת הפקודה שלו. התיקייה וה-branch נכתבים כשאפשר לזהות בשורת הפקודה נתיב
בתוך checkout (`git -C <dir> branch --show-current`); אחרת כותבים שה-branch לא ידוע.

```powershell
# Windows
$p = (Get-NetTCPConnection -LocalPort <port> -State Listen).OwningProcess | Select-Object -First 1
Get-CimInstance Win32_Process -Filter "ProcessId=$p" | Select-Object ProcessId, Name, CommandLine
```
```bash
# Linux / macOS
lsof -nP -iTCP:<port> -sTCP:LISTEN
```

### עצירה

לפי ה-PIDs בקובץ הרישום, עם כל העץ שלהם: `taskkill /PID <pid> /T /F` ב-Windows, `kill <pid>`
במקום אחר. אחר כך בודקים שהפורטים פנויים, ומוחקים את הקובץ. ב-merge זה קורה **לפני** מחיקת
ה-worktree: ב-Windows אי אפשר למחוק תיקייה שתהליך רץ ממנה.

האפליקציה חיה כל עוד הסשן שהרים אותה פתוח. סשן שנסגר עוצר אותה, והקובץ נשאר: פורט פנוי עם
רישום פירושו רישום ישן, ומוחקים אותו.
